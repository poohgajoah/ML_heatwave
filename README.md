**안심온**은 여러 노인을 관리하는 사회복지사가 폭염 때 **누구에게 먼저, 어떤 조치를, 어디로 안내할지** 한 화면에서 판단하도록 돕는 웹 서비스예요.

```
ML 온열질환 위험도 예측 → RAG 기반 행동지침·무더위쉼터 추천(TMAP 거리 검증)
  → 예방 전화 자동 발신 → 응답 분석 → 도움 필요 시 지원 업무 생성
```

| 파트 | 구성 |
|---|---|
| **ML (본인)** | **학습 데이터 구축, 피처 설계, XGBoost 위험도 예측 모델, 추론, 평가** |
| LLM·RAG | 온열질환 대응지침 검색, 행동지침 생성 |
| 백엔드 | Spring Boot, MySQL, 전체 연동 |
| 전화 기능 | 예방 전화 발신, 대화 흐름, 재시도 |
| 디자인·데이터 | 화면 설계, 공공데이터 수집 |

이 모델의 위험도 점수는 서비스에서 **어떤 노인을 먼저 챙길지 우선순위를 정하는 입력값**으로 쓰여요.

## 📌 문제 정의

폭염은 고령층에게 특히 위험하지만, 기존 폭염특보는 **지역별 노인 온열질환 발생 위험**을 직접 알려주지 않습니다.
그래서 두 단계로 예측하는 모델을 만들었습니다.

1. **다음 날 폭염 예측**: 최근 7일 기상 데이터로 내일 폭염 여부(O/X)를 예측합니다. (서울)
2. **노인 온열질환 발생 예측**: 그날의 기상 조건으로 해당 지역에 65세 이상 온열질환자가 발생할 확률을 계산합니다. (전국 시 단위)

## 🗂️ 데이터

| 데이터 | 출처 | 내용 |
|---|---|---|
| 날씨 이슈별 데이터(폭염) | 기상청 | 2019~2026년 5~9월 일별·지점별 체감온도, 기온, 습도, 폭염특보, 열대야, 자외선 등 |
| 온열질환 감시 데이터 | 질병관리청 | 온열질환자 발생일자, 나이, 발생 지역 |

- 전처리 결과는 약 **18만 행**(일자 × 지역 155곳)이고, 타깃은 `온열질환자(노인)발생여부`(O/X)예요.
- 양성 비율은 **약 4.5%** 로 클래스 불균형이 심한 데이터입니다.

## ⚙️ 처리 과정

```
월별 기상 CSV 40개 ─┐
                    ├─ 전처리 ─ 지역 매칭 ─ 학습/튜닝 ─ 임계값 선택 ─ 예측 CLI
질병청 온열질환 CSV ─┘
```

**전처리** (`preprocessing/preprocess.py`)
- CP949/UTF-8가 섞인 월별 CSV를 병합하고 날짜 형식을 통일했어요.
- 관측 지점명을 행정구역명으로 정규화했어요. (예: `북강릉 → 강릉`, `서귀포 → 제주`)
- 온열질환 데이터에서 **65세 이상**만 골라 시 단위 지역으로 묶었어요.
- 두 데이터에 모두 있는 지역만 남기고, 날짜·지역이 일치하는 행에 발생 여부를 붙였어요.

**모델링**
- 범주형 변수는 OneHotEncoder, 결측치는 SimpleImputer로 처리하고 XGBoost와 함께 sklearn Pipeline으로 묶었어요.
- 데이터는 **연도 기준으로 분할**했어요. 학습 2019–2023, 검증 2024, 테스트 2025라서 미래 데이터가 학습에 섞이지 않아요.
- 불균형은 `scale_pos_weight`로 보정했어요.
- 하이퍼파라미터는 넓게 탐색한 뒤 좁혀서 다시 탐색하는 2단계로 튜닝했어요.
- 폭염 예측 모델은 직전 **7일치 기상값을 lag 특성으로 펼쳐서** 사용해요.

**임계값 선택** (`training/tune_threshold.py`)
- 환자를 놓치는 비용(False Negative)이 더 크다고 보고, **Recall 0.8 이상을 유지하면서 F1이 최대**인 임계값을 골랐어요.

## 📊 결과 (2025년 테스트셋)

### 1) 노인 온열질환 발생 예측 (전국 155개 지역)

| 지표 | 값 |
|---|---|
| Recall | **0.844** |
| Precision | 0.128 |
| F1 | 0.222 |

- 실제 발생 사례(일자 × 지역) 1,028건 중 **868건을 잡아냈어요.**
- 양성 비율이 4.5%라서, 무작위로 찍었을 때 Precision은 약 0.045예요. 이 모델은 그보다 **약 2.8배 정확**해요.
- Precision이 낮은 건 놓치지 않는 쪽(Recall)을 우선한 설계라서 생기는 트레이드오프예요.

### 2) 다음 날 폭염 예측 (서울)

| 지표 | 검증(2024) | 테스트(2025) |
|---|---|---|
| Accuracy | 0.856 | **0.870** |
| Recall | 0.771 | **0.935** |
| Precision | 0.675 | 0.630 |
| F1 | 0.720 | **0.753** |
| ROC-AUC | 0.914 | **0.957** |
| PR-AUC | 0.768 | **0.835** |

테스트셋의 실제 폭염일 31일 중 **29일을 맞혔어요.**

## 🚀 실행 방법

```bash
pip install -r requirements.txt

# 내일 서울의 폭염 여부와 노인 온열질환 위험도 예측
python main.py 2026-08-18 서울

# 기상 CSV를 넣어 노인 온열질환 위험도 일괄 예측
python predict.py input.csv -o outputs/predictions.csv
```

실행 예시:
```
예측일/지역: 2026-08-18 / 서울
폭염 확률: 0.067534, 폭염 예측: X
노인 온열질환 위험도: 0.823778
```

다시 학습하려면 아래 순서로 실행하세요.
```bash
python preprocessing/preprocess.py
python training/train_xgboost.py
python training/tune_threshold.py
python training/evaluate_test.py
python training/train_next_day_heatwave.py
```

## 📁 구조

```
├── main.py                  # 날짜·지역 입력 → 폭염 + 노인 온열질환 위험도 예측

├── preprocessing/           # 데이터 병합·정제
├── training/                # 학습, 튜닝, 임계값 선택, 테스트 평가
├── models/                  # 학습된 파이프라인(.joblib)과 설정(.json)

└── outputs/                 # 튜닝 결과, 예측 결과
```

## 🔧 한계와 개선 방향

- 폭염 예측 모델은 현재 **서울만** 지원해요. 다른 지역으로 넓히는 게 다음 과제예요.
- 다음 날 노인 온열질환 위험도는 과거 비슷한 날짜(±15일, 같은 폭염 상태)의 기상 중앙값으로 추정해요. 실제 기상 예보 API를 연동하면 정확도를 높일 수 있어요.
- 인구 대비 고령 인구 비율, 냉방 시설 같은 지역 특성 변수를 추가해 볼 수 있어요.
